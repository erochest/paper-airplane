# 04: Reply Dispatch from a Claude Code Session

**What to build:** Inside a Claude Code Session, `fly reply` reads the current Session's transcript and sends the most recent Long Reply (more than 300 words, counting prose and code) as a Reply Dispatch. The content is taken word for word from the transcript and never retyped by the agent (see ADR 0002). The name uses the Reply's own timestamp and the Session Title.

**Blocked by:** 03

**Status:** ready-for-agent

- [x] The transcript is located from `CLAUDE_CODE_SESSION_ID` and the current project's directory under the Claude Code projects folder.
- [x] Transcript reading sits behind a host interface (Session → ordered prompts/Replies with timestamps), so a second host (Pi, ticket 08) can be added without touching Long Reply selection, naming, or the Flight Log.
- [x] Reply text is assembled from assistant `text` blocks for that Reply. Thinking, tool use, tool results, `isMeta` injections and bookkeeping records are left out.
- [x] The most recent Long Reply is selected, so trailing short Replies like "Done." are skipped. If there is no Long Reply, the command says so clearly and sends nothing.
- [x] The name is `YYYY-MM-DD HH:MM <Session Title>` using the Reply's timestamp.
- [x] Session Title order of preference: `--title`, then the title already fixed for this Session in the Flight Log, then Claude Code's generated title. If none exists, the CLI exits saying a title is needed, so the agent can propose one.
- [x] The Session Title is fixed in the Flight Log at the Session's first Dispatch. The Flight Log records the Session ID, host and source reply reference.
- [x] Unrecognised transcript record shapes cause a clear, loud error, not silent dropping.
- [x] Scrubbed Claude Code fixture transcripts cover: trailing short Replies, multi-block Replies with interleaved tool calls, `isMeta` injections, a Session with and without a generated title.

## Comments

- Implemented. Notes for later tickets:
  - A Reply is every assistant `text` block from one prompt to the next (any non-`isMeta` user record that isn't only tool results), not one API request. Its reference is the uuid of the record holding its first text block. Its timestamp is the time of its last text block.
  - "Loud error" covers records that carry a `message`: an unknown record type with a message, or an unknown user or assistant content block. Records with no `message` are treated as bookkeeping and skipped, because Claude Code adds new ones often.
  - `custom-title` (a user `/rename`) is preferred over `ai-title` as the host's title.
  - `--title` on a later Dispatch names only that Dispatch. The Session Title fixed at the first Dispatch is not changed (`INSERT OR IGNORE`), so the next run without `--title` goes back to it. If story 23 ("fix a poor automatic title") should change the fixed title, that is a small change in `FlightLog.record`.
  - The transcript is looked for under the encoded `cwd` first, then in every project directory. `CLAUDE_CONFIG_DIR` is honoured.
  - Long Reply word counting splits on whitespace, so Markdown markers (`#`, `-`, fences) count as words.
  - Fixtures are generated by `test/fixtures/claude-code/generate.ts`.
